# MedQuiz 題庫新增介紹與架構說明

## 檔案結構規範 (File Structure)

在執行新增作業前，請務必了解系統之檔案配置結構，所有題庫資源皆統一存放於 `content/` 目錄下：

```text
medquiz/
├── index.html          # 系統核心程式 (包含題庫目錄註冊與 Firebase 配置)
├── content/            # 題庫資源根目錄
│   └── [subject-folder]/   # 科目資料夾 (例如: y3s2-anatomy-final)
│       ├── unit.json       # 單元索引檔 (定義該科目內的所有單元)
│       ├── JSON/           # 單元題目資料目錄 (.json)
│       │   ├── B04.json
│       │   └── B05.json
│       └── images/         # 圖片資源目錄
│           ├── B04/        # 與 JSON 檔名對應的圖片子目錄
│           │   ├── B04_1.webp
│           │   └── B04_2.webp
│           └── B05/
│               └── B05_1.webp
```

- **`index.html`**: 系統核心，所有科目的入口皆須於 `src/js/subjects.js` 的 `SUBJECT_DATA` 陣列中進行註冊。
- **科目資料夾**: 存放於 `content/` 下，命名規範見下文。
- **`unit.json`**: 科目內的單元索引。
- **`JSON/`**: 存放格式化題目資料。
- **`images/`**: 存放 WebP 格式圖片，建議依單元建立子目錄。

---

## 命名規範 (Naming Conventions)

為了維持系統自動化處理的準確性，請務必遵守以下命名慣例：

### 1. 科目資料夾命名
規範格式：`[學年][學期]-[學科]-[考試階段]`
- 範例：`y3s2-anatomy-final` (三年級下學期-大體解剖-期末考)
- 範例：`y3s1-histology-mid` (三年級上學期-組織學-期中考)

### 2. 單元檔案與目錄
- **JSON 檔案**：建議使用簡短代碼或英文描述，如 `B04.json`, `Heart.json`。
- **圖片子目錄**：在 `images/` 下建立的子目錄名稱必須與對應的 JSON 檔名 **完全一致**（不含 .json）。
    - 範例：`JSON/B04.json` 對應 `images/B04/`。

### 3. 題目編號與圖片檔名
- **題目編號 (`num`)**：建議格式為 `[單元名]_[序號]`。
    - 範例：`B04_1`, `B04_2`。
- **圖片路徑 (`path`)**：慣例為 `[單元名]/[單元名]_[序號].webp`。
    - 範例：`B04/B04_1.webp`。

## 題庫新增步驟

### 第一步：建立科目資料夾
於 `content/` 目錄下建立新資料夾（例如：`y3s2-neuro-mid`）。
並於該資料夾內建立 `JSON/` 與 `images/` 兩個子目錄。

### 第二步：配置單元索引檔 `unit.json`
於科目資料夾根路徑建立 `unit.json`：

```json
[
    {
        "id": "B04.json",
        "name": "B04：顳下窩與下頜區"
    },
    {
        "id": "B05.json",
        "name": "B05：頸部深層構造"
    }
]
```

### 第三步：編製題目資料至 `JSON/`
於 `JSON/` 中建立對應檔案。單筆題目範例如下：

```json
[
  {
    "num": "B04_1",
    "path": "B04/B04_1.webp",
    "answer": ["Buccal nerve", "頰神經"],
    "explanation": "與 parotid duct 平行，注意與 buccal artery 之區分。",
    "description": ""
  }
]
```
### 第四步：圖片資源處理與存放
若題目包含圖片，請依據以下規範處理後存放於 `images/` 目錄：
1. **格式規範**：所有圖片資源必須轉換為 **WebP** 格式。
2. **品質優化**：轉檔時請設定圖片品質為 **75%**，以確保在維持清晰度的前提下優化載入速度。
3. **目錄編制**：建議於 `images/` 內建立子目錄（如 `ch1_images/`）進行分類。
4. **路徑一致性**：確保 JSON 檔案中 `path` 欄位填寫之間接路徑與實際存放路徑完全一致。

---

### 第五步：於 `index.html` 註冊科目入口
完成資源配置後，須將科目資訊註冊至系統首頁：
1. 開啟 `src/js/subjects.js`。
2. 於對應年級區塊加入科目配置物件：

```javascript
{ 
  year: "三年級", 
  title: "神經解剖學", 
  subtitle: "三下期中", 
  icon: "brain", 
  url: "/content/y3s2-neuro-mid" 
},
```

**參數定義：**
- `year`: 分類標籤，決定該科目顯示於何種年度分頁。
- `title`: 主標題，顯示於卡片顯目位置。
- `subtitle`: 副標題，用於備註期中/期末等資訊。
- `icon`: 採用 [Lucide Icons](https://lucide.dev/icons/) 圖標庫。請填寫對應之圖標名稱。
- `url`: **關鍵參數**。必須以 `/content/` 開頭，後接你在第一步建立之**科目資料夾名稱**。路徑錯誤將導致系統無法載入資源。

---

## 技術注意事項與建議
1. **JSON 格式驗證**：JSON 語句必須嚴格遵守標準語法（如：不可遺漏逗號、引號需成對等）。建議於發布前使用 JSON 驗證工具（如 JSONLint）進行檢查。
2. **答題進度同步 (Firebase)**：系統將自動以註冊的 `url` 作為資料庫節點（自動轉換為合法路徑），無須額外修改 Firebase 後端邏輯。
3. **效能優化**：請務必執行第四步之圖片壓縮規範，以避免大量圖片造成行動裝置存取效能低落。
4. **路徑大小寫**：Linux 系統區分大小寫，請確保 JSON 中的 `path` 與實際檔案路徑完全一致。
